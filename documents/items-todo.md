#### Pattern unit split
Planned 2026-11-09. `TPattern` (`Sloper.Core.Pattern`, about 3,950 lines and 161 methods) is the whole editing API in one class: the graph, names, formulas and evaluation, and also materials and the cut list, transforms, markings and notches, notes, merging and breaking points, changing a point's or edge's type, offset runs and round corners, pieces, seams and grainlines. Its routines are short and well commented; the trouble is breadth, and 71 units use it, so the public API stays as it is while the code moves out, behind thin wrappers. Pascal has no package-wide visibility, so moving operations out means making a small editing kernel public. Include files would split the file but not the class, so they are not used. No behaviour changes; done first, 2026-11-09: misplaced interface comments, `FNameExclude` replaced by an explicit exclusion in `DerivedEdgeName`, and `Notes`, `MeasurementFile`, `Identity` and `View` as properties (`TPatternView` is a class the pattern owns, so its fields can still be set one by one).
